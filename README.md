허용된 Google 계정끼리 일정과 할 일을 공유하는 작은 대시보드입니다.
순수 HTML/CSS/JavaScript로 만들었으며 npm·빌드 도구는 필요 없습니다.
폰에서 읽기 편한 전체 설명서는 **[START_HERE.html](START_HERE.html)** 입니다.

## 이미 연결한 사용자의 업데이트

1. 최신 ZIP을 풀고 dashboard-v1 안의 파일을 사용합니다.
2. 기존 저장소를 새로 만들려면 START_HERE.html의 삭제 → 새 저장소 → Pages 순서를 따릅니다.
3. 파일 전부를 저장소 첫 화면에 올립니다. ZIP 자체와 개인 일정 백업은 올리지 않습니다.
4. 화면의 `v1.11 · 공동 일정` 표시와 Google 로그인·공동 일정 연결을 확인합니다.
5. 이번에는 규칙 갱신이 필요합니다. UPDATE.html의 복사 버튼으로 게시한 뒤 파일을 올립니다.
6. Firebase 프로젝트·members·tasks는 삭제하거나 다시 만들지 않습니다.

GitHub를 새로 만들어도 Firebase 데이터는 유지됩니다. 새 저장소에는 과거 저장소를 복제하지 말고
이번 ZIP만 올려 이전 기록을 가져오지 않도록 합니다. 같은 소유자·같은 저장소명이면 Pages 주소도 같습니다.
다른 이름이면 주소의 마지막 경로가 달라집니다. GitHub 저장소명과 Firebase 프로젝트명은 달라도 됩니다.

## 공개 파일과 개인정보

- README·코드·주석·설정 안내에는 실제 이메일·이름·일정·비밀번호를 넣지 않습니다.
- owner@example.com과 member@example.com은 설명용 예시이며 실제 허용 목록에 그대로 등록하지 않습니다.
- 실제 사용자 이메일은 Firebase 관리 화면의 members에 입력합니다. 앱에서 전체 회원 목록을 읽거나 고치지 못합니다.
- 일정과 작성자·수정자 정보는 Firestore에 저장하고, 허용된 로그인 사용자에게만 화면으로 보여줍니다.
- config.js의 apiKey, authDomain, projectId, appId는 브라우저 연결에 필요한 공개 설정입니다.
  설정을 숨기는 대신 Firestore 규칙이 실제 데이터 접근을 제한합니다. 타인용으로 재사용할 때는 본인 프로젝트 값으로 바꿉니다.
- 서비스 계정 JSON·비밀키·Google 비밀번호·실제 일정 JSON 백업·개인 화면 캡처는 GitHub에 올리지 않습니다.
- GitHub 커밋 작성자 이메일은 별개입니다. 계정 Settings → Emails → Keep my email addresses private를 켜세요.
  Git 명령어로 업로드할 경우 GitHub의 noreply 이메일 설정도 필요합니다. 공개 프로필 이름·사용자명은 별도로 확인합니다.
- 파일 교체만으로 과거 커밋의 개인정보가 없어지지 않습니다. 저장소 재생성 절차는 START_HERE.html에 있습니다.
  삭제해도 다른 사람이 받은 복사본·fork를 회수하지는 못합니다.

## 화면과 사용법

- 입력 영역(목록 아래): 시작일·종료일, 제목, 마감일(오늘/내일/날짜 없음/날짜 선택), 중요 여부를 입력해 추가합니다.
- 먼저 챙길 일: 미완료 중 중요하거나 시작일이 앞으로 7일 이내인 항목입니다. 진행 중인 기간도 포함합니다. 지난 기한도 포함하며 마감순으로 정렬합니다.
- D-3, 오늘, 2일 지남 등으로 남은 기간을 표시합니다. 나머지·완료 목록은 접어서 보관합니다.
- 하단: 이번 달부터 3개월 달력. 화살표로 한 달씩 이동하고 이번 달 버튼으로 돌아옵니다.
- 날짜 선택: 그날 항목을 표시하고 새 입력의 마감일도 맞춥니다. 항목 선택: 수정 창을 엽니다.
- 완료·미완료 전환과 삭제를 지원합니다. 삭제는 영구 삭제이며 휴지통은 없습니다.
- 수정 창에 작성자·마지막 수정자·시각을 표시합니다. 모든 허용 사용자가 모든 일정을 수정할 수 있습니다.
- 달 아이콘은 밝기 전환, 톱니바퀴는 큰 글씨와 백업 설정입니다. 좁은 화면은 입력·목록부터 세로로 쌓습니다.
- 여러 기기에서 변경이 실시간으로 반영됩니다. 다른 사람이 먼저 수정한 오래된 편집 창은 저장을 거절합니다.
- 인터넷이 끊기면 이미 받은 목록만 보여주고 편집을 막습니다. 오프라인 저장 대기열은 사용하지 않습니다.

## 태블릿과 자동 갱신

가로로 거치하고 전용 Google 계정을 members에 등록해 로그인합니다.
화면 자동 꺼짐은 Android 설정에서 조절합니다. 웹앱이 화면 켜짐을 강제하지는 않습니다.
한국시간 0·6·12·18시에 페이지 새로고침을 시도하며, 입력·저장·로그인·팝업 처리 중에는 보류합니다.
숨겨진 탭이나 OS가 멈춘 브라우저에서는 정시 실행을 보장하지 않습니다. 다시 활성화되면 갱신 여부를 확인합니다.
수동 새로고침도 서버에서 최신 자료를 다시 불러옵니다. 새로고침 전에 입력 중인 내용은 저장하세요.

## 데이터 항목

Firestore의 tasks 컬렉션에 항목별 문서를 저장합니다. 문서 ID가 고유번호입니다.

| 항목 | 형식 / 의미 |
| --- | --- |
| id | 문서 고유번호. 화면과 백업에 포함하며 문서 내부에는 중복 저장하지 않음 |
| title | 제목, 공백 제외 빈 제목 불가·최대 120자 |
| dueDate | 종료일/마감일 YYYY-MM-DD 또는 null(날짜 없음). 기존 필드 유지 |
| startDate | 시작일 YYYY-MM-DD 또는 null. 예전 자료에 없으면 dueDate와 같은 날 |
| important | 중요 여부 true/false |
| completed | 완료 여부 true/false |
| completedAt | 완료 시각 또는 null |
| createdAt / createdBy | 작성 시각 / 작성 계정 |
| updatedAt / updatedBy | 마지막 수정 시각 / 수정 계정 |
| revision | 변경 횟수. 다른 기기와 수정 충돌을 판단 |
| schemaVersion | 현재 데이터 형식 번호 1 |
| restoredAt / restoredBy | 백업에서 가져온 경우만: 가져오기 시각 / 실행 계정 |

계정 기록은 `{ id, name, email }`입니다. 신규 작성·일반 수정·복구 실행자 기록은 로그인 계정과 서버 시각을 검증합니다.
Firestore의 시각은 Timestamp 형식이며, storage.js가 화면·백업용 ISO 문자열로 변환합니다.
예전 자료에 없는 필드는 기본값으로 보완하고 모르는 추가 JSON 필드는 보존합니다.
백업 원본의 작성자·시각은 파일 기록을 복원한 것이며 진위를 증명하는 기록은 아닙니다.
복구 실행자·시각은 별도로 서버에서 검증하고 이후 일반 편집으로 바꿀 수 없습니다.

## 사용자 추가·해제

1. Firebase → Firestore Database → 데이터 → members → 문서 추가.
2. 문서 ID에 사용자의 실제 Google 이메일을 소문자로 직접 입력합니다. 자동 ID를 쓰지 않습니다.
3. 필드 enabled, 유형 boolean(켜짐/꺼짐), 값 true를 설정하고 저장합니다.
4. 해당 계정으로 대시보드에 로그인합니다. 규칙이나 GitHub 코드를 고칠 필요 없습니다.
5. 해제할 때 enabled를 false로 바꿉니다. 다시 허용하려면 true로 돌립니다.

문자열 "true"는 boolean true와 다릅니다. 문서 ID의 앞뒤 공백·탭도 다른 문자이므로 주의합니다.
프로젝트 관리자도 앱에서는 members 등록이 필요합니다. 공동 사용자에게 Firebase 관리자 권한을 줄 필요 없습니다.
클라이언트는 자기 회원 문서만 조회하며 전체 회원 목록 조회·회원 문서 수정은 서버에서 거절합니다.

## 백업과 복구·이전

1. 온라인으로 연결된 상태에서 톱니바퀴 → JSON 내보내기를 누릅니다.
2. 폰의 내 파일 → 다운로드에서 our-day-backup으로 시작하는 .json을 확인합니다.
3. 복구는 JSON 가져오기 → 파일 선택 → 추가/건너뜀 개수 확인 → 없는 항목 추가 순서입니다.
4. 같은 고유번호가 있으면 내용이 달라도 건너뜁니다. 기존 내용을 과거 상태로 덮어쓰지 않습니다.
5. 도중에 중단되면 이미 추가된 항목은 남습니다. 같은 파일로 재시도하면 중복을 건너뜁니다.

전체 일정과 완료 항목을 백업합니다. members·로그인 정보·Firebase 설정은 포함하지 않습니다.
다른 Firebase로 이전하려면 새 프로젝트의 설정·규칙·회원 등록을 끝내고 config.js를 새 연결정보로 바꾼 뒤 가져옵니다.
복구는 10MB 이하 JSON만 지원합니다. format=our-day-backup, version=1, exportedAt=ISO 시각, tasks=항목 배열입니다.
파일 형식·모든 항목을 먼저 검사하고 확인 버튼 전에는 저장하지 않습니다. 서버에서 거절되면 일부만 추가될 수 있습니다.
같은 제목이라도 ID가 다르면 다른 항목입니다. 임의 수정한 ID로 가져오면 중복처럼 보일 수 있습니다.
새 버전 번호의 데이터는 현재 앱에서 가져오지 않고 앱 업데이트를 요구합니다.
일반 JSON 필드 외 Firestore 특수 자료형(참조·좌표 등)의 임의 확장은 별도 변환 구현이 필요합니다.

수정 전 ZIP과 개인 일정 JSON을 각각 보관합니다. 한 번에 작은 변경을 하고 로그인·추가·수정·백업을 확인하세요.
정적 파일을 바꾼 뒤 오래된 화면이 계속 보이면 index.html의 파일 주소 뒤 ?v=6 숫자를 새 번호로 바꿉니다.
규칙을 바꿀 때는 firestore.rules뿐 아니라 두 안내 HTML의 rules-text도 동일하게 갱신한 뒤 Firebase에 게시합니다.
GitHub 파일을 커밋하는 것만으로 Firestore 서버 규칙은 바뀌지 않습니다.

## Windows 11 / PowerShell에서 미리보기

GitHub Pages로 사용하면 Python은 필요 없습니다. PC에서 파일을 수정하며 확인할 때만 사용합니다.
Python을 설치한 뒤 index.html이 있는 폴더의 탐색기 주소창에 powershell을 입력합니다.

```powershell
# 최초 한 번: 프로젝트 전용 가상환경 생성
py -m venv .venv
# 매번: 가상환경 안의 Python으로 실행(활성화 명령 불필요)
.\.venv\Scripts\python.exe -m http.server 8000 --bind 127.0.0.1
```

브라우저에서 http://localhost:8000을 엽니다. 파일 더블클릭(file://) 방식은 사용하지 않습니다.
로컬 로그인은 Firebase Authentication 승인된 도메인에 localhost를 추가해야 합니다.
종료는 PowerShell에서 Ctrl+C입니다. .venv 폴더는 GitHub에 업로드하지 않습니다.

## 확인 방법과 알려진 제한

- 로그인 전: 시크릿 탭에서 일정 제목이 없고 입력·백업이 잠겨 있는지 확인합니다.
- 미허용 계정: 로그인은 되더라도 실제 일정 읽기·쓰기는 거절돼야 합니다.
- 서버 규칙: Firestore → 규칙 → 규칙 플레이그라운드에서 get, /tasks/시험문서ID, 인증 끄기로 시험하면 거부돼야 합니다.
- 실시간: 서로 다른 기기의 허용 계정으로 추가·수정·완료를 확인합니다.
- 충돌: 두 기기에서 같은 항목 편집 후 먼저 저장한 값이 오래된 창에 덮어써지지 않는지 확인합니다.
- 복구: 같은 파일을 바로 가져오면 추가 0개. 시험 항목만 백업 후 삭제하고 가져오면 해당 1개만 복원합니다.
- 오프라인: 기존 목록 조회는 되지만 입력은 막혀야 합니다. 연결 후 서버 확인이 끝나면 다시 편집됩니다.
- 허용 해제: 다른 시험 계정의 enabled=false가 온라인 기기에서 반영되면 목록을 지워야 합니다. 시험 후 true로 복원합니다.

이미 보거나 복사한 정보를 회수할 수는 없습니다. 오프라인 기기는 기존 목록을 보이며 재연결 후 권한 해제를 확인합니다.
일정은 영구 디스크 캐시를 켜지 않고 메모리에 보관합니다. 로그인 유지 정보와 화면 설정은 브라우저에 남을 수 있습니다.
인터넷 없이 페이지 자체를 새로 열거나 새로고침하면 사이트가 열리지 않을 수 있습니다.
Firestore 사용량에서 읽기·쓰기·저장을 확인하세요. 재접속·전체 목록 수신·회원 확인·백업도 사용량에 포함됩니다.
무료 한도 초과 시 동작이 멈출 수 있습니다. Spark를 유지하고 유료 업그레이드하지 않습니다.

검증 이력: 5단계에서 로컬 Firestore 규칙 엔진 19개, 저장 담당 모의 시험 19개,
백업 파일 검사·확인 전 무저장·취소·중복 건너뜀·중단·로그아웃 잠금 검증을 통과했습니다.
6단계는 문서·개인정보 제거·버전 표시를 정리하고 배포 파일의 개인정보·링크·규칙 일치·구문을 확인합니다.
실제 사용자 기기의 모든 기능 검증을 대신하는 것은 아니므로 위 확인 순서를 진행해주세요.
휴지통·이미지 저장·긴급 알림은 이번 버전에 포함하지 않습니다.

## v1.11: 기간과 작성자 색상

이번 업데이트는 UPDATE.html 순서대로 진행합니다. 기존 저장소를 삭제하지 말고 파일을 교체합니다.
기존 config.js의 Firebase 연결정보를 유지하며 tasks·members를 초기화하지 않습니다.
기존 하루 일정·완료 여부·문서 ID·작성 기록은 그대로 읽습니다. 시작일 없는 자료는 종료일과 같은 날로 해석합니다.
기간을 설정하면 시작일과 종료일을 모두 포함해 표시하고 수정·완료·삭제는 일정 전체에 적용됩니다.
날짜별 별개 문서를 만들지 않으므로 중간 날짜에 눌러도 같은 일정입니다.
먼저 챙길 일은 중요·기한 지남·진행 중·시작일까지 7일 이내인 항목이며 종료일 순으로 정렬합니다.

색상 설정: Firestore settings/appearance 문서에 skyEmail·pinkEmail 문자열로 실제 작성자 이메일을 넣습니다.
이메일은 공개 파일에 넣지 않습니다. 읽기는 허용 계정만, 쓰기는 Firebase 관리 화면에서만 가능합니다.
기존 일정의 createdBy.email도 사용하므로 재등록하지 않습니다. 작성자 이메일이 없는 예전 항목은 기본색입니다.
중요 빨간색 > 작성자 하늘색/핑크색 > 기본색 순으로 적용합니다. 색 변수는 styles.css의 --tone-*입니다.
설정 문서는 일정 JSON 백업에 포함하지 않으므로 다른 Firebase로 옮길 때 색상 설정도 직접 등록합니다.

호환 방침: 새 필드는 기본값으로 보완하고 기존 문서·필드를 유지합니다. 업데이트만으로 기존 자료를 삭제하지 않습니다.
향후 구조 전환이 꼭 필요하면 먼저 백업·이전 방법을 안내합니다. 새 기능 자료를 이전 앱으로 되돌리는 역방향 호환은 보장하지 않습니다.

이전 v1.1 검증: 보안 규칙 엔진 23개, 저장 담당 19개, 기존/기간 일정·7일 경계·색상 우선·백업 시험 통과. 브라우저에서 새 배치와 입력 영역을 확인했습니다. 실제 계정 색상과 기기 간 동기화는 Firebase 설정 후 확인하세요.
