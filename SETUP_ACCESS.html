공동 일정 사용자 등록

owner@example.com과 member@example.com은 설명용 예시입니다. 그대로 등록하지 마세요. 실제 Google 이메일은 Firebase 관리 화면에만 입력하며, README·코드·GitHub 커밋 메시지에 적지 않습니다. 이미 등록을 마쳤다면 다시 만들지 않습니다.

로그인 확인을 마쳤습니다. 이제 허용 목록을 만들고 보안 규칙을 교체합니다. 모든 설정은 Spark 무료 요금제에서 진행하며 카드 등록이 필요 없습니다.

1. 새 파일을 GitHub에 올리기

  1. 최신 ZIP을 다운로드하고 압축을 풉니다.
  2. GitHub schedule-dashboard → Code → Add file → Upload files에서 새 dashboard-v1 안의 파일들을 업로드합니다. ZIP 자체를 올리지 않습니다.
  3. Commit directly to the main branch → Commit changes를 누릅니다.
  4. Pages 게시 후 사이트를 새로고침하여 v1 · 공동 일정 표시를 확인합니다.

기존 Firebase 연결정보와 Google 로그인 설정은 유지됩니다. 아직 아래 설정 전이라면 접근 거절이 표시돼도 정상입니다.

2. 본인 계정 허용하기

  1. Firebase 관리 화면에서 본인의 Firebase 프로젝트 프로젝트를 엽니다.
  2. Firestore → 데이터(Data) → 컬렉션 시작(Start collection)을 누릅니다. Authentication의 승인된 도메인 메뉴가 아닙니다.
  3. 컬렉션 ID에 members를 입력하고 다음으로 갑니다.
  4. 문서 ID는 자동 ID 대신 본인의 실제 Google 이메일을 입력합니다. 아래 표는 형식 예시입니다.
  5. 필드 이름은 enabled, 유형은 boolean(불리언), 값은 true로 선택합니다.
  6. 저장(Save)을 누릅니다.

boolean은 켜짐·꺼짐을 뜻합니다. 문자열(string)로 “true”를 입력하면 안 됩니다.

3. 공동 사용자 계정 허용하기

  1. 방금 만든 members를 선택하고 문서 추가(Add document)를 누릅니다.
  2. 문서 ID에 공동 사용자의 실제 Google 이메일을 입력합니다.
  3. 동일하게 enabled / boolean / true를 입력하고 저장합니다.
컬렉션문서 ID필드·유형·값
membersowner@example.comenabled · boolean · true
membersmember@example.comenabled · boolean · true

본인은 Firebase 프로젝트 관리자이지만 앱에서는 두 사람 모두 같은 일정 수정 권한을 갖습니다. 공동 사용자에게 Firebase 프로젝트 관리 권한을 따로 줄 필요는 없습니다.

4. 보안 규칙 교체하기

  1. 아래 보안 규칙 복사를 누릅니다.
  2. Firebase의 Firestore → 규칙(Rules) 탭으로 갑니다.
  3. 기존 내용을 모두 지운 뒤 붙여넣고 게시(Publish)를 누릅니다.
  4. 대시보드로 돌아와 다시 연결을 누릅니다. 규칙 반영에 잠시 걸릴 수 있습니다.

규칙 내용 펼치기 · 직접 선택해서 복사할 수도 있어요
// 허용 목록 변경은 Firebase 관리 화면에서만 합니다. 앱은 자기 등록 여부만 읽습니다.
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    function googleUser() {
      return request.auth != null
        && request.auth.token.email is string
        && request.auth.token.email_verified == true
        && request.auth.token.firebase.sign_in_provider == 'google.com';
    }
    function allowed() {
      return googleUser()
        && get(/databases/$(database)/documents/members/$(request.auth.token.email.lower())).data.enabled == true;
    }
    function actor(value) {
      return value is map && value.keys().hasOnly(['id', 'name', 'email'])
        && value.id == request.auth.uid && value.email == request.auth.token.email
        && value.name is string && value.name.size() > 0 && value.name.size() <= 200;
    }
    // 시작일 없는 기존 문서는 종료일 하루 일정으로 계속 허용합니다.
    function dates(data) {
      let start = data.get('startDate', data.dueDate);
      return (start == null && data.dueDate == null) ||
        (start is string && data.dueDate is string && start <= data.dueDate
        && start.matches('^[0-9]{4}-(0[1-9]|1[0-2])-(0[1-9]|[12][0-9]|3[01])$'));
    }
    // 새 필드가 없는 기존 자료는 종일·공동 일정으로 허용합니다.
    function options(data) {
      let assignee = data.get('assigneeEmail', null);
      let allDay = data.get('allDay', true);
      let start = data.get('startDate', data.dueDate);
      let first = data.get('startTime', null);
      let last = data.get('endTime', null);
      return (assignee == null || (assignee is string && assignee.size() <= 254 && assignee.matches('^[^ @]+@[^ @]+[.][^ @]+$')))
        && (data.get('scope', 'shared') == 'private' || assignee == null)
        && allDay is bool && data.get('scope', 'shared') in ['shared', 'private']
        && (allDay ? (first == null && last == null) :
          (start is string && data.dueDate is string && first is string
          && first.matches('^([01][0-9]|2[0-3]):[0-5][0-9]$')
          && (last == null || (last is string && last.matches('^([01][0-9]|2[0-3]):[0-5][0-9]$')
          && (start < data.dueDate || (start == data.dueDate && first < last))))));
    }
    function content(data) {
      return options(data) && dates(data) && data.title is string && data.title.size() > 0 && data.title.size() <= 120
        && (data.dueDate == null || (data.dueDate is string
          && data.dueDate.matches('^[0-9]{4}-(0[1-9]|1[0-2])-(0[1-9]|[12][0-9]|3[01])$')))
        && data.important is bool && data.completed is bool
        && data.revision is int && data.revision > 0
        && data.updatedAt == request.time && actor(data.updatedBy);
    }
    // 백업 원본의 작성 정보는 사용자 파일의 기록이며, 복구 실행자는 별도로 검증합니다.
    function oldPerson(value) {
      return value is map && value.id is string && value.name is string && value.email is string;
    }
    function oldTime(value) { return value == null || value is timestamp; }
    function restored(data) {
      return options(data) && dates(data) && data.restoredAt == request.time && actor(data.restoredBy)
        && data.title is string && data.title.size() > 0 && data.title.size() <= 120
        && (data.dueDate == null || (data.dueDate is string
          && data.dueDate.matches('^[0-9]{4}-(0[1-9]|1[0-2])-(0[1-9]|[12][0-9]|3[01])$')))
        && data.important is bool && data.completed is bool
        && data.revision is int && data.revision >= 0 && data.schemaVersion == 1
        && oldTime(data.createdAt) && oldTime(data.updatedAt) && oldTime(data.completedAt)
        && (data.completed || data.completedAt == null)
        && oldPerson(data.createdBy) && oldPerson(data.updatedBy);
    }
    // 계정 목록은 공개하지 않습니다. 미등록 사용자도 자기 등록 여부만 확인할 수 있습니다.
    match /members/{email} {
      allow get: if googleUser() && email == request.auth.token.email.lower();
      allow list, write: if false;
    }
    // 색상 설정은 허용된 사람만 읽으며 Firebase 관리 화면에서만 수정합니다.
    match /settings/appearance { allow get: if allowed(); allow list, write: if false; }
    match /tasks/{taskId} {
      allow read: if allowed();
      allow create: if allowed() && content(request.resource.data)
        && request.resource.data.keys().hasOnly(['title', 'dueDate', 'startDate', 'allDay', 'startTime', 'endTime', 'scope', 'assigneeEmail', 'important', 'completed',
          'completedAt', 'createdAt', 'createdBy', 'updatedAt', 'updatedBy', 'schemaVersion', 'revision'])
        && request.resource.data.schemaVersion == 1 && request.resource.data.revision == 1
        && request.resource.data.createdAt == request.time && actor(request.resource.data.createdBy)
        && request.resource.data.completedAt == (request.resource.data.completed ? request.time : null);
      allow create: if allowed() && restored(request.resource.data);
      // 작성자·작성 시각 및 나중에 추가한 필드는 그대로 보존합니다.
      allow update: if allowed() && content(request.resource.data)
        && request.resource.data.diff(resource.data).affectedKeys().hasOnly([
          'title', 'dueDate', 'startDate', 'allDay', 'startTime', 'endTime', 'scope', 'assigneeEmail', 'important', 'completed', 'completedAt', 'updatedAt', 'updatedBy', 'revision'])
        && request.resource.data.revision == resource.data.get('revision', 0) + 1
        && request.resource.data.completedAt == (request.resource.data.completed
          ? (resource.data.get('completed', false) && resource.data.get('completedAt', null) != null
              ? resource.data.completedAt : request.time) : null);
      allow delete: if allowed();
    }
    // 위에 명시하지 않은 위치(진단·하위 문서 포함)는 모두 차단합니다.
    match /{document=**} { allow read, write: if false; }
  }
}

이 규칙은 Google로 로그인했고, 이메일 확인을 마쳤으며, members의 해당 이메일이 enabled=true인 사람만 일정에 접근하게 합니다. 허용 목록은 앱에서 추가·수정·삭제할 수 없습니다. 본인의 Firebase 관리 화면에서만 바꿉니다.

5. 두 기기에서 확인하기

  1. 본인 계정으로 로그인한 화면에 공동 일정에 연결됐어요가 나오는지 확인합니다.
  2. 시험용 제목 공유 연결 시험으로 할 일을 하나 추가합니다.
  3. 공동 사용자 폰에서 같은 사이트를 열고 허용 목록에 등록한 본인 계정으로 로그인합니다. 새로고침 없이 같은 일이 보이는지 확인합니다.
  4. 공동 사용자 폰에서 제목·마감일·중요 여부를 바꾸고, 본인 폰에도 반영되는지 확인합니다.
  5. 항목을 눌러 수정 창에서 작성자는 본인, 마지막 수정자는 공동 사용자인지 확인합니다.
  6. 완료 → 미완료 변경도 서로 반영되는지 확인합니다. 완료한 일은 접힌 목록에서 찾을 수 있습니다.
  7. 시험 항목을 삭제하면 양쪽에서 사라지는지 확인합니다. v1에는 휴지통이 없고 되돌릴 수 없습니다.

6. 로그인하지 않은 상태와 권한 해제 시험

  • 시크릿 탭에서 사이트를 열어 로그인 버튼만 보이고 일정 제목이 나오지 않는지 확인합니다. 입력도 잠겨 있어야 합니다.
  • 허용 목록에 없는 다른 Google 계정이 있다면 로그인하여 허용 목록에 없는 계정과 빈 일정을 확인합니다.
  • 서버 차단은 Firestore → 규칙 → 규칙 플레이그라운드(Rules playground)에서도 시험합니다. 작업은 get, 위치는 /tasks/실제시험문서ID, 인증은 끄기로 선택하고 실행하면 거부여야 합니다. 문서 ID는 데이터 탭의 tasks에서 확인합니다.
  • 공동 사용자 계정의 members 문서에서 enabled를 false로 바꾸면, 온라인인 공동 사용자 화면에서 목록과 입력이 잠기는지 확인합니다. 확인 후 true로 되돌립니다.

서버는 목록에서 해제된 사람의 새 요청을 거절합니다. 이미 보았거나 복사한 내용을 되돌려 없애는 기능은 아닙니다. 인터넷이 끊긴 기기는 이미 받은 목록을 표시하며, 재연결되어 해제를 확인하면 지웁니다.

7. 오프라인과 수정 충돌 확인

  • 일정이 보이는 폰에서 인터넷을 끄면 오프라인 안내가 나오고 기존 목록만 볼 수 있어야 합니다. 입력·수정·삭제는 막힙니다.
  • 연결 복구 뒤 서버 확인이 끝나면 편집이 다시 가능합니다. 오프라인에서 페이지 자체를 새로 열거나 새로고침하면 사이트가 열리지 않을 수 있습니다.
  • 두 기기에서 같은 항목의 수정 창을 열고 한쪽에서 먼저 저장합니다. 나머지 기기의 오래된 수정 창으로 저장하면 충돌 안내가 나오며, 닫았다가 다시 열어 수정합니다.

태블릿·새 사용자 추가와 해제

members에서 새 Google 이메일을 문서 ID로 추가하고 enabled를 boolean true로 설정합니다. 태블릿에서 그 계정으로 로그인하면 됩니다. 규칙 파일을 다시 고칠 필요는 없습니다.

해제는 해당 문서의 enabled를 false로 바꾸면 됩니다. 다시 허용할 때 true로 바꿉니다. 이메일은 Google 로그인 화면에 표시되는 주소 그대로 소문자로 입력하며, 앞뒤 공백이나 탭을 넣지 않습니다. 겉보기에는 같아도 숨은 탭이 있으면 다른 문서입니다. 문제가 있으면 주소를 직접 다시 입력해 새 문서를 만드세요.

members의 다른 필드는 필요 없습니다. 실제 일정용 tasks는 앱에서 첫 항목을 추가할 때 생성됩니다. tasks 내용을 관리 화면에서 직접 고치면 시각·변경 횟수가 맞지 않을 수 있어 앱에서 편집하세요.

오류와 무료 사용량

접근이 거절되면 프로젝트 ID, 로그인 이메일, members 문서 ID, enabled의 boolean 유형, 규칙 게시 여부를 차례로 확인하고 다시 연결을 누릅니다.

장기간 켜 둔 패널의 목록 수신과 허용 목록 확인도 Firestore 읽기 사용량에 포함됩니다. 무료 사용량은 Firebase의 사용량 화면에서 확인하세요. 한도에 도달하면 오류가 날 수 있으므로 Spark를 유지하고 유료 전환하지 않습니다.

규칙 엔진 시험 19개와 저장 담당 모의 시험 19개를 통과했습니다. 실제 두 계정·두 기기 확인은 위 절차로 진행합니다. 백업은 백업 안내를 참고하세요.
