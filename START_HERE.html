우리의 하루 사용 설명서

기존 사용자의 v1.13 업데이트는 여기를 먼저 보세요. 저장소를 다시 만들 필요 없습니다.

허용된 Google 계정끼리 일정과 할 일을 공유하는 대시보드입니다. 공개 파일에는 실제 사용자 이메일·이름·일정이 없습니다. 계정 등록은 Firebase에서만 합니다.

이번 버전 적용

이미 Firebase 연결을 마쳤다면 설정을 처음부터 반복하지 않습니다. 아래 순서로 GitHub 저장소만 새로 만들 수 있습니다. Firebase 프로젝트·members·일정 데이터는 그대로 둡니다.

  1. 최신 ZIP을 다운로드하고 압축을 풉니다. dashboard-v1 안에 index.html과 config.js가 있는지 확인합니다.
  2. 기존 대시보드에서 가능하면 JSON 내보내기로 일정 백업도 개인 다운로드 폴더에 보관합니다. 이 백업은 GitHub에 올리지 않습니다.
  3. 이전 ZIP이나 저장소의 복사본 대신 이번 ZIP의 파일만 새 저장소에 올립니다.

1. 기존 GitHub 저장소 삭제

  1. 삭제할 저장소를 열고 Settings를 누릅니다. 폰에서 안 보이면 상단 More 메뉴를 확인합니다.
  2. General 화면 맨 아래 Danger Zone → Delete this repository를 누릅니다.
  3. I want to delete this repository → 경고 확인 → I have read and understand these effects를 누릅니다.
  4. 요청된 저장소 이름을 정확히 입력하고 Delete this repository를 누릅니다.

이 작업은 해당 저장소의 코드·기록·이슈·설정을 없애며 사이트도 잠시 열리지 않습니다. Firebase는 삭제하지 않습니다. 다른 사람이 이미 받은 복사본이나 fork까지 지우는 것은 아닙니다.

2. 새 저장소 생성과 파일 업로드

  1. GitHub에 로그인합니다. 처음이면 Sign up에서 계정을 만들고 이메일 인증을 마칩니다.
  2. 상단 + → New repository를 누릅니다.
  3. Repository name에 원하는 이름(예: schedule-dashboard)을 입력하고 Public을 선택합니다. 같은 소유자·같은 이름으로 재생성하면 Pages 주소도 같습니다. Firebase 프로젝트명과 일치할 필요 없습니다.
  4. Add a README file을 켜고 Create repository를 누릅니다.
  5. Code → Add file → Upload files → choose your files에서 새 dashboard-v1 안 파일 전부를 선택합니다. ZIP이나 폴더 자체를 올리지 않습니다.
  6. Commit directly to the main branch → Commit changes를 누릅니다. 커밋 메시지에 이메일·개인 일정을 넣지 않습니다.

GitHub 커밋 작성자 정보도 공개될 수 있습니다. GitHub 계정 Settings → Emails → Keep my email addresses private를 켠 뒤 업로드하세요. 명령어로 올리는 경우에는 GitHub가 제공하는 비공개용 noreply 이메일을 별도로 설정해야 합니다. GitHub 프로필 이름과 사용자명은 공개 정보입니다.

3. 웹주소 켜기

  1. 새 저장소 Settings → 왼쪽 Pages를 엽니다.
  2. Build and deployment → Source를 Deploy from a branch로 선택합니다.
  3. Branch는 main, 폴더는 /(root)를 선택하고 Save를 누릅니다.
  4. 게시가 끝나면 같은 Pages 화면 위에 사이트 주소와 Visit site 버튼이 나옵니다. 버튼이 없으면 Actions에서 작업이 끝났는지 확인하고 Pages 화면을 새로고침합니다.
  5. Visit site를 눌러 v1.13 · 공동 일정 표시를 확인하고 로그인합니다.

기본 주소는 https://GitHub사용자명.github.io/저장소이름/ 입니다. 배포에는 몇 분이 걸릴 수 있습니다. 저장소 이름을 바꿨으면 폰·태블릿 즐겨찾기도 새 주소로 바꿉니다.

4. Firebase를 유지하고 확인

  • config.js의 기존 공개 연결정보를 유지하면 같은 일정 데이터에 연결됩니다.
  • v1.1 규칙을 게시하지 않았다면 백업 안내의 보안 규칙 복사로 교체·게시합니다.
  • 같은 GitHub 계정이면 승인된 로그인 도메인도 같습니다. 다른 계정이나 도메인이면 도메인 등록을 합니다.
  • 새 사용자·태블릿 계정은 사용자 등록 안내를 따릅니다. 실제 이메일은 Firebase의 members에만 입력합니다.

5. 최종 확인

  1. 일반 탭에서 로그인하고 시험 항목을 추가합니다. 다른 허용 계정의 기기에 새로고침 없이 보이는지 확인합니다.
  2. 날짜·중요·완료 표시를 바꾸고 서로 반영되는지, 작성자·수정자 표시가 맞는지 확인합니다.
  3. 시크릿 탭에서 사이트를 열면 실제 일정 제목이 없어야 합니다. 등록하지 않은 계정으로 로그인해도 읽거나 입력할 수 없어야 합니다.
  4. 서버 차단 시험은 규칙 플레이그라운드 안내를 따릅니다.
  5. 내보내기·가져오기 시험으로 기존 항목 건너뛰기와 시험 항목 복원을 확인합니다.
  6. 인터넷을 끄면 상태 안내와 편집 잠금이 나오는지 확인합니다.
  7. 새 저장소에서 owner@example.com 같은 예시만 있고 실제 이메일·이름이 없는지 확인합니다. 과거 파일을 다시 올리지 않습니다.

일상 사용과 태블릿

제목·마감일·중요 여부를 입력해 추가합니다. 날짜를 누르면 그날 항목을 보고 입력 날짜도 맞출 수 있습니다. 항목을 누르면 수정 창이 열립니다. 나머지·완료 목록은 제목을 눌러 펼칩니다. 달 아이콘으로 밝기, 톱니바퀴에서 글씨 크기를 바꿉니다.

태블릿은 가로로 두고 허용한 전용 계정으로 로그인합니다. Android 설정에서 화면 자동 꺼짐을 가능한 범위에서 조정하세요. 이 웹앱 자체가 화면 켜짐을 강제하지는 않습니다.

한국시간 0·6·12·18시에 페이지 갱신을 시도합니다. 입력·저장·로그인·팝업 진행 중 또는 숨겨진 탭이면 보류합니다. OS가 브라우저를 멈추면 정확한 시각을 보장할 수 없으며 다시 활성화된 후 확인합니다. 수동 새로고침도 최신 자료를 다시 읽습니다.

v1에는 휴지통·캐릭터 이미지·긴급 알림이 없습니다. 삭제는 영구 삭제이며, 이전 백업이 있다면 없는 항목 추가 방식으로 복구할 수 있습니다.

파일 수정과 처음 설정

파일 역할·데이터 항목·자주 바꾸는 값·Windows 실행법은 README.md에 있습니다. 새 Firebase 프로젝트를 만드는 경우에는 처음 Firebase 연결부터 진행합니다.
