처음 Firebase 연결하기

이미 공동 일정에 연결됐다면 이 설정은 완료된 것입니다. 저장소를 새로 만들더라도 Firebase 프로젝트는 유지합니다.

1. 프로젝트와 웹 앱

  1. Firebase 콘솔에 Google 계정으로 로그인합니다.
  2. 프로젝트 만들기 → 원하는 이름 입력 → 안내에 따라 생성합니다. Google Analytics는 이 앱에 필요 없으므로 끌 수 있습니다.
  3. Spark 무료 요금제를 유지합니다. 카드 등록과 Blaze 업그레이드는 하지 않습니다.
  4. 프로젝트 개요에서 웹 아이콘(</>) 또는 프로젝트 설정 → 일반 → 내 앱 → 앱 추가 → 웹을 선택합니다.
  5. 앱 닉네임을 입력하고 등록합니다. Firebase Hosting은 선택하지 않습니다.
  6. SDK 설정에서 CDN 또는 script 태그 방식을 봅니다. npm 설치는 하지 않습니다. 이 앱은 storage.js에 고정 버전이 이미 연결돼 있습니다.
  7. 표시된 firebaseConfig의 apiKey, authDomain, projectId, appId 네 값을 config.js의 해당 항목에 넣습니다. 기존 설정이 입력돼 있다면 그대로 유지합니다.

2. Firestore

  1. Firestore Database → 데이터베이스 만들기를 누릅니다.
  2. 에디션을 물으면 Standard, 데이터베이스 ID는 (default)를 사용합니다.
  3. 위치는 이용 지역에 맞게 선택합니다. 한국 이용이면 서울(asia-northeast3)을 선택할 수 있습니다. 위치는 생성 뒤 쉽게 바꾸지 못하므로 확인합니다.
  4. 보안 모드를 물으면 프로덕션 모드를 선택합니다. 전체 공개 테스트 규칙은 사용하지 않습니다.
  5. 허용 목록 안내의 규칙 복사 버튼으로 firestore.rules 전체를 복사해 규칙(Rules)에 붙여넣고 게시합니다.

3. 계정 연결과 사용량

Google 로그인 설정 → 사용자 등록 순서로 진행합니다. tasks는 앱에서 첫 일정을 추가하면 생깁니다.

Firestore의 사용량(Usage)에서 읽기·쓰기·저장 사용량을 확인합니다. 실시간 연결·재접속·백업도 사용량에 포함됩니다. 무료 한도 초과 시 기능이 멈출 수 있습니다. Cloud Storage·Cloud Functions·유료 관리형 백업·TTL 자동 삭제는 쓰지 않습니다.

공개 연결 설정은 비밀번호가 아닙니다. 실제 접근은 로그인과 Firestore 규칙으로 제한합니다. 서비스 계정 JSON·비밀키·Google 비밀번호는 GitHub에 올리지 않습니다.
